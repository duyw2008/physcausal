# 诺特闹理论 — 费曼脑进化哲学

> 版本: v2.0.0 | 日期: 2026-07-21
>
> **诺特闹**（Nous）不是产品名，是一种设计哲学：**只给容量，不给方法。只造生态，不定规则。**

---

## 一、核心理念

### 1. 云，不是池

人脑不冷冻神经元。神经元只有一个状态——活着。区别不在细胞活性，在突触权重。不活跃的神经元不是"休眠"，是**暂时没人跟它说话**。

```
旧架构（冷池模型）：
  hot_pool ← freeze ← 活跃 → wake → cold_pool → 永久休眠 ❌

新架构（统一云）：
  memory ← 沉淀 ← 所有细胞 → 孵化 ← disk_shelf ✓
                       ↓
                  活性由上游输入决定
                  低活性自然休眠（涌现，非行政命令）
                  概念热了自动拉回
```

**核心洞察：** 活性不是状态标签，是涌现行为。神经元自己决定此刻是否 walk，基于它的 reward、图度和近期活跃频率。

### 2. 给容量，不给方法

每次改动前先问："这是给容量还是给方法？"

- **给容量** ✓：数学引擎（可问公式）、因果图（可游走）、冷池经验、矛盾追踪、coincidence
- **给方法** ✗：游走策略、验证标准、研究方向、知识结构

脑获得的是工具，不是指令。所有方向选择都来自脑自己的 coincidence 数据和图的拓扑。

### 3. 拓扑即认知

认知操作不是外部函数调用，是**图上游走**。`_trace_to_action` 沿 causes 边从矛盾节点走到 action——这个游走本身就是推理。当图长出新型边，新推理路径自然涌现。

**方法论不在代码里，在拓扑里。**

## 二、生态系统：四个垃圾免疫机制

> 不是加一个"垃圾检测器"，是创造一个垃圾活不下去的环境。

| 机制 | 人脑对应 | 实现 |
|------|---------|------|
| **(A) 代谢成本** | 神经元维持动作电位消耗能量 | tier4 基础衰减 ×3.0 |
| **(B) 相干场** | 孤立细胞被修剪 | 不连接 tier≤2 的边额外衰减 ×1.5 |
| **(C) 用进废退** | Hebbian：一起放电的连在一起 | tier4 失活窗口缩为 1/3，超半窗再加罚 ×1.5 |
| **(D) 晋升窗口期** | 发育期后不用的突触消除 | tier4 超 200 代未晋升 → 直接消除 |

四个机制叠加生效，不是顺序筛选。弱边承受指数级衰减压力，强边几乎不受影响。

## 三、睡眠消化：五个映射

| 人脑睡眠功能 | 费曼脑对应 |
|-------------|-----------|
| **记忆回放**（海马→皮层） | 反向重放 walk_memory，弱强化(0.3) |
| **突触降尺度**（SHY 假说） | 全局 s×0.8，s<0.01 的边消除 |
| **系统整合**（统计规律提取） | walk_buffer 累计 50 代后消化进突触权重 |
| **创造性重组**（REM 期） | 跨 walk 共享节点 → 组合新捷径边（上限 400） |
| **代谢废物清除**（类淋巴系统） | _audit_t3_noise + _sort_graph_by_edge_s |

**走步消化的折中方案：** walk_memory 保留 50 代窗口再消化，给"重新解释"留时间窗口。不立即消化也不永久保留。

## 四、磁盘种子库

> 冯诺依曼架构的癌症是存储和计算分离。接受这个限制，把 I/O 税交在最值的地方。

```
_cell_shelf = {
    "黑洞": [genome_A, genome_B, ...],   ← 只存genome (~300B)
    "量子纠缠": [genome_C, ...],          ← 不存 walk_memory
}
```

| | 内存 | 磁盘 |
|---|---|---|
| 细胞状态 | 热点细胞 (~10K) | genome 种子（无上限） |
| walk_memory | 保留 50 代 | 不存——消化完就排掉 |
| 突触权重 | 全部（图是脑本身） | 仅快照备份，不分页 |

**沉淀**：内存超 20K → 低活性细胞 genome 入盘 → 释放内存
**孵化**：概念变热 → 从盘拉 genome → `EvolvableCell.from_seed()` → 回内存

## 五、薄云休眠

不是"这个细胞被冻住了"，是"这个细胞当前没有足够的上游输入"。

```python
activity_score = reward × graph_degree × walk_rate_last_10_gens
walk_chance   = min(1.0, score / median_score)

if random.random() < walk_chance:
    cell.step()   # 闪电区，参与 walk
else:
    pass          # 薄云区，自然跳过这代
```

高活性细胞高频 walk，低活性细胞偶尔 walk。**所有细胞都有机会亮，但亮的频率由自身状态决定。** 这不是行政调度，是涌现。

## 六、从 v1 到 v2 的进化

| | v1 冷池架构 | v2 统一云架构 |
|---|---|---|
| 核心理念 | 热/冷 行政分界 | 活性涌现，一张图 |
| 冷池角色 | 永久休眠停尸房 | 磁盘种子库（可拉回） |
| 细胞唤醒 | 永远不唤（headroom=0） | 概念热了自动孵化 |
| 磁盘写什么 | 完整 cell dict（含 walk） | 只有 genome（~300B） |
| walk 持久化 | 永存冷池 | 50代消化窗口 |
| 代码量 | +230行冷池管理 | -230行（全部砍掉） |
| 内存预算 | 6K（硬上限） | ~10-20K（涌现平衡） |
| 磁盘预算 | 冷池 336MB/次写 | 种子库 KB 级/次 |
